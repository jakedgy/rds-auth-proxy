# Aurora Express IAM Token Path Compatibility

## Context

Aurora PostgreSQL clusters created with express configuration use an internet
access gateway and IAM-only authentication. The repository's current AWS SDK
generates a correctly signed RDS IAM token whose serialized URL has an empty
path:

```text
host:5432?Action=connect&...
```

AWS CLI serializes the same signed token with an explicit root path:

```text
host:5432/?Action=connect&...
```

The tokens have identical decoded parameters and signatures, but the express
internet gateway rejects the pathless form with `PAM authentication failed`.

## Design

Keep AWS SDK token generation and the normal AWS credential chain unchanged.
Immediately after `auth.BuildAuthToken` succeeds, pass its result through a
small pure helper that inserts `/` before the first query delimiter when the
token does not already contain a path separator there.

The helper will:

- Convert `host:port?...` to `host:port/?...`.
- Leave `host:port/?...` unchanged.
- Leave strings without a query delimiter unchanged.

This avoids duplicating SigV4 signing logic and does not introduce an AWS CLI
runtime dependency. A dependency upgrade alone is insufficient because the
current AWS Go SDK still emits the pathless serialization.

## Testing

Add table-driven unit coverage for missing, present, and inapplicable token
paths. Follow test-driven development: add the regression test and observe the
expected failure before implementing the helper and wiring it into `runToken`.

Verification will include:

1. The focused token-path unit test.
2. The complete Go test suite.
3. A live token generated by the updated binary authenticating directly to the
   sandbox Aurora PostgreSQL 17 express cluster.
4. A live PostgreSQL query through the local TCP proxy using a freshly
   generated token.

All live database verification is read-only.
